    odoo.abugharbia.com/v1¶

    Package v1 contains API Schema definitions for the odoo v1 API group

    Resource Types¶

    • OdooBackup
    • OdooBackupStore
    • OdooDeployment
    • OdooRestore

    BackupConsistency¶

    Underlying type: string

    BackupConsistency is how a backup keeps the database and the filestore in step.

    Validation: - Enum: [Online Offline]

    Appears in: - OdooBackupConfig

    Field Description
    Online BackupConsistencyOnline backs up while Odoo keeps serving: the dump and
    the list of files come from one database snapshot, and files deleted
    meanwhile are taken from the previous backup.
    Offline BackupConsistencyOffline stops Odoo for the backup.

    BackupCopy¶

    BackupCopy is one copy of a backup in another store.

    Appears in: - OdooBackupStatus

    Field Description Default Validation
    store string Store is the OdooBackupStore holding the copy.
    snapshotID string SnapshotID of the copy in that store's repository; empty when the
    copy failed.
    file string File is the copy in a store of format zip: the Odoo zip's path below
    the store's root.
    error string Error says why the copy failed.

    BackupSource¶

    BackupSource is a backup that is not one of the instance's own OdooBackups: an Odoo backup file (.zip or .dump, as Odoo's database manager makes them) or a snapshot in any restic repository, in an OdooBackupStore of the same namespace.

    Appears in: - BootstrapFromBackup - OdooRestoreSpec

    Field Description Default Validation
    store string Store is the OdooBackupStore that holds the backup. MaxLength: 253
    MinLength: 1
    path string Path inside the store, below its path (or subPath). A path ending in
    .zip or .dump is an Odoo backup file; its last segment may be a
    pattern (*, ?, [a-z]), and the match whose name sorts last, the
    newest for dated names, is restored. Any other path is a restic
    repository folder; empty is this instance's own repository
    (<namespace>/<name>).    		 MaxLength: 512
    Pattern: ^([A-Za-z0-9._~+@=-]+/)*[A-Za-z0-9._~+@=*?\[\]-]+$
    snapshot string Snapshot in a restic repository: its ID, or latest (default) for the
    newest snapshot with Host and Tags.    		 Pattern: ^(latest\|[0-9a-f]\{8,64\})$
    host string Host picks latest among the snapshots of one restic --host, such as
    <namespace>/<name> for the operator's own snapshots.    		 MaxLength: 253
    tags string array Tags picks latest among the snapshots that have all these restic
    tags, such as deployment=<namespace>/<name>.    		 MaxItems: 10
    items:MaxLength: 253

    BackupStoreFormat¶

    Underlying type: string

    BackupStoreFormat is how backups are kept in a store.

    Validation: - Enum: [restic zip]

    Appears in: - OdooBackupStoreSpec

    Field Description
    restic BackupStoreFormatRestic keeps one encrypted, deduplicated restic
    repository per OdooDeployment.
    zip BackupStoreFormatZip keeps every backup as the zip Odoo's database
    manager makes, unencrypted and not deduplicated, in one folder per
    OdooDeployment. A zip store only receives copies.

    BeforeUpgrade¶

    Underlying type: string

    BeforeUpgrade says whether a backup is taken before an upgrade.

    Validation: - Enum: [Off BestEffort Required]

    Appears in: - OdooBackupConfig

    Field Description
    Off BeforeUpgradeOff upgrades without a backup first.
    BestEffort BeforeUpgradeBestEffort takes a backup first and upgrades even when
    it fails.
    Required BeforeUpgradeRequired upgrades only after the backup succeeded; a
    failed backup keeps the running image.

    Bootstrap¶

    Bootstrap says how an instance's database is made on first boot.

    Appears in: - OdooDeploymentSpec

    Field Description Default Validation
    fromBackup BootstrapFromBackup FromBackup restores a backup instead of initializing a new database:
    the way an existing Odoo moves onto the operator, or an instance is
    recreated from its backups. It is used once, before Odoo first
    starts; later changes are ignored.    		 Optional: {}

    Appears in: - Bootstrap

    Field Description Default Validation

    MinLength: 1
    path string Path inside the store, below its path (or subPath). A path ending in
    .zip or .dump is an Odoo backup file; its last segment may be a
    pattern (*, ?, [a-z]), and the match whose name sorts last, the
    newest for dated names, is restored. Any other path is a restic
    repository folder; empty is this instance's own repository
    (<namespace>/<name>).    		 MaxLength: 512
    Pattern: ^([A-Za-z0-9._~+@=-]+/)*[A-Za-z0-9._~+@=*?\[\]-]+$
    snapshot string Snapshot in a restic repository: its ID, or latest (default) for the
    newest snapshot with Host and Tags.    		 Pattern: ^(latest\|[0-9a-f]\{8,64\})$
    host string Host picks latest among the snapshots of one restic --host, such as
    <namespace>/<name> for the operator's own snapshots.    		 MaxLength: 253
    tags string array Tags picks latest among the snapshots that have all these restic
    tags, such as deployment=<namespace>/<name>.    		 MaxItems: 10
    items:MaxLength: 253
    neutralize boolean Neutralize runs Odoo's neutralize on the restored database before
    Odoo first starts on it, and gives it a new database.uuid (see
    OdooRestore spec.neutralize). Set it for a copy of production.

    BootstrapStatus¶

    BootstrapStatus records the restore spec.bootstrap.fromBackup started.

    Appears in: - OdooDeploymentStatus

    Field Description Default Validation
    restore string Restore is the OdooRestore that restores the backup.
    completed boolean Completed is set once it has restored the backup.

    DatabaseCreatePolicy¶

    Underlying type: string

    DatabaseCreatePolicy tells the operator what to do when the database named in spec.database does not exist.

    Validation: - Enum: [IfNotExists Never]

    Appears in: - OdooDatabaseConfig

    Field Description
    IfNotExists DatabaseCreatePolicyIfNotExists creates the database when it is missing and
    adopts it as an external database when it already exists.
    Never DatabaseCreatePolicyNever never creates a database; a missing database is reported as Degraded.

    DeletionPolicy¶

    Underlying type: string

    DeletionPolicy tells the operator what to do with an owned resource when the OdooDeployment is deleted.

    Validation: - Enum: [Retain Delete]

    Appears in: - OdooDatabaseConfig - PersistentVolumeClaimSpec

    Field Description
    Retain
    Delete

    MaintenanceJobStatus¶

    MaintenanceJobStatus records the maintenance Job (init or upgrade) the operator is waiting for. The JSON keys keep the 0.2.x names.

    Appears in: - OdooDeploymentStatus

    Field Description Default Validation
    name string The name of the Job
    jobNamespace string The namespace of the Job
    kind string Kind is "init" or "upgrade"
    image string Image the Job runs; becomes status.appliedImage on success
    token string Token is the spec.upgrade.token the Job was created for; becomes status.appliedUpgradeToken on success
    modules string array The list of modules that are being installed (-i)
    upgradeModules string array The list of modules that are being upgraded (-u)
    startedAt Time StartedAt is when the operator created the Job.

    MaintenancePageConfig¶

    MaintenancePageConfig controls the page the http Service serves while Odoo itself cannot answer: during the init and upgrade Jobs and until the Deployment has an available replica again.

    Appears in: - OdooDeploymentSpec

    Field Description Default Validation
    enabled boolean Enabled runs a small <name>-maintenance Deployment from the operator's
    own image and points the http Service at it whenever Odoo has no
    available replica (and spec.replicas is not 0). The poll Service always
    stays on Odoo.    		 false
    title MaintenancePageText Title is the product name the page shows ("Updating <title>"). Odoo MaxLength: 64
    MinLength: 1
    Pattern: ^[^\n\r<>]*$
    titleTranslations object (keys:string, values:MaintenancePageText) TitleTranslations replaces the title for a page language. The page is
    shown in English or Arabic, picked from the browser's Accept-Language,
    so the only key it reads today is "ar".    		 MaxProperties: 8
    accentColor string AccentColor is the page's accent, as #rrggbb. #714b67 Pattern: ^#[0-9A-Fa-f]\{6\}$
    logo string Logo is shown instead of the title's initial. It must be a base64 data
    URI: Odoo is not answering while the page is up, so the page cannot
    load images from it.    		 MaxLength: 65536
    Pattern: ^data:image/(png\|jpeg\|gif\|webp\|svg\+xml);base64,[A-Za-z0-9+/]+=*$

    MaintenancePageText¶

    Underlying type: string

    MaintenancePageText is one line of text shown on the maintenance page.

    Validation: - MaxLength: 64 - MinLength: 1 - Pattern: ^[^\n\r<>]*$

    Appears in: - MaintenancePageConfig

    NFSStore¶

    NFSStore is an NFS export, mounted into the backup Jobs. The nodes need an NFS client and a route to the server.

    Appears in: - OdooBackupStoreSpec

    Field Description Default Validation
    server string Server is the NFS server's host name or address. MinLength: 1
    path string Path is the exported folder. Repositories go under <path>/<namespace>/<deployment>/. Pattern: ^/

    OdooBackup¶

    OdooBackup is one full backup of an OdooDeployment: its database and its filestore, taken together. Create one to take a backup now. It is not owned by the OdooDeployment, so deleting an instance never deletes its backups.

    Field Description Default Validation
    apiVersion string odoo.abugharbia.com/v1
    kind string OdooBackup
    metadata ObjectMeta Refer to Kubernetes API documentation for fields of metadata.
    spec OdooBackupSpec
    status OdooBackupStatus

    OdooBackupConfig¶

    OdooBackupConfig turns on backups of this instance.

    Appears in: - OdooDeploymentSpec

    Field Description Default Validation
    stores string array Stores are OdooBackupStores in this namespace. Backups are written to
    the first; the instance's repository is <path>/<namespace>/<name>/
    inside it. Each backup is then copied to the other stores.    		 MaxItems: 4
    items:MinLength: 1
    schedule string Schedule takes a backup on a cron schedule ("0 3 * * *" or @daily), in
    TimeZone. Empty (the default) takes no scheduled backups. A schedule
    missed while the operator was down runs once when it is back.    		 MaxLength: 100
    timeZone string TimeZone of Schedule, the drill schedule and the retention rules, as an
    IANA name such as Europe/Berlin.    		 UTC MaxLength: 100
    retention OdooBackupRetention Retention says which backups are kept after each backup. { }
    drill OdooBackupDrill Drill restores the newest backup on a schedule to prove it works. Optional: {}
    beforeUpgrade BeforeUpgrade BeforeUpgrade takes a backup before each upgrade (a new spec.image or
    spec.upgrade.token), with Odoo stopped so the backup holds the data
    exactly as the upgrade found it. Off (default) upgrades without one;
    BestEffort upgrades even when the backup fails; Required keeps the
    running image when it fails, until the failed OdooBackup is deleted
    (which tries again) or the upgrade target changes.    		 Off Enum: [Off BestEffort Required]
    consistency BackupConsistency Consistency: Online (default) backs up while Odoo keeps serving;
    Offline stops Odoo for the backup.    		 Online Enum: [Online Offline]
    restore OdooRestoreConfig Restore holds the defaults of in-place restores (OdooRestore). { }
    resources ResourceRequirements Resources of the backup and restore Jobs. Optional: {}
    activeDeadlineSeconds integer ActiveDeadlineSeconds bounds one backup or restore Job. 21600 Minimum: 60

    OdooBackupDrill¶

    OdooBackupDrill restores the newest backup on a schedule to prove it can be restored, without touching the running instance.

    Appears in: - OdooBackupConfig

    Field Description Default Validation
    schedule string Schedule in cron format, in spec.backup.timeZone; empty turns drills off. MaxLength: 100
    scratchSizeLimit Quantity ScratchSizeLimit caps the node disk the drill's scratch filestore
    (an emptyDir) may use; unset leaves it uncapped. A drill that needs
    more is evicted and reported failed.    		 Optional: {}

    OdooBackupRetention¶

    OdooBackupRetention says which backups are kept. Scheduled backups are thinned with restic's keep rules (daily: 7 keeps the newest backup of each of the last 7 days that have one; a backup kept by any rule stays); manual backups keep their newest Manual and pre-upgrade backups their newest PreUpgrade. A backup with spec.keep, and the newest backup, are never deleted. Unset fields take the defaults below.

    Appears in: - OdooBackupConfig

    Field Description Default Validation
    last integer Last keeps the newest N backups. Minimum: 0
    hourly integer Hourly keeps the newest backup of each of the last N hours that have one. Minimum: 0
    daily integer Daily keeps the newest backup of each of the last N days that have one. 7 Minimum: 0
    weekly integer Weekly keeps the newest backup of each of the last N weeks that have one. 4 Minimum: 0
    monthly integer Monthly keeps the newest backup of each of the last N months that have one. 12 Minimum: 0
    yearly integer Yearly keeps the newest backup of each of the last N years that have one. Minimum: 0
    within string Within keeps every backup newer than this, counted from the newest
    backup, such as 30d, 12h or 1y6m (restic's duration format).    		 Pattern: ^([0-9]+[ymdh])*$
    manual integer Manual keeps the newest N manual backups; 0 keeps them all. Minimum: 0
    preUpgrade integer PreUpgrade keeps the newest N backups taken before upgrades; 0 keeps
    them all.    		 5 Minimum: 0
    keepAll boolean KeepAll turns retention off: no backup is ever deleted.

    Appears in: - OdooDeploymentStatus

    Field Description Default Validation
    lastScheduleTime Time LastScheduleTime is the latest scheduled time the operator has handled,
    whether it took a backup then or skipped it.
    nextScheduleTime Time NextScheduleTime is when the next scheduled backup is due.
    schedule string Schedule and TimeZone the times above were computed for.
    timeZone string
    lastDrillScheduleTime Time LastDrillScheduleTime is the latest drill time the operator has handled.
    nextDrillTime Time NextDrillTime is when the next drill is due.
    drillSchedule string DrillSchedule the drill times above were computed for.
    drillDue Time DrillDue is the scheduled time of a drill waiting in the instance's
    queue.
    lastDrill OdooDrillResult LastDrill is the result of the latest restore drill.
    lastSuccessfulDrillTime Time LastSuccessfulDrillTime is when a restore drill last passed.

    OdooBackupStatus¶

    OdooBackupStatus describes one backup.

    Appears in: - OdooBackup

    Field Description Default Validation
    phase string Phase: Pending, WaitingForFilestoreCleanup, Running, Completed,
    CompletedWithWarnings, PartiallyCompleted (taken, but a copy to another
    store failed) or Failed.    		 Enum: [Pending WaitingForFilestoreCleanup Running Completed CompletedWithWarnings PartiallyCompleted Failed]
    message string Message explains the phase in a sentence.
    store string Store is the OdooBackupStore the backup was written to.
    repository string Repository is the restic repository inside the store, <namespace>/<deployment>.
    snapshotID string SnapshotID is the restic snapshot holding this backup.
    consistency string Consistency the backup was taken with: Online or Offline.
    job string Job is the Job taking the backup. Attempts counts the Jobs started for it.
    attempts integer
    retryAfter Time RetryAfter is when a backup that waited for Odoo's filestore cleanup
    is tried again.
    waitingSince Time WaitingSince is when the backup started waiting for Odoo's filestore
    cleanup to finish.
    startedAt Time StartedAt is when the backup Job was created.
    completedAt Time CompletedAt is when the backup finished, successfully or not.
    image string Image is the Odoo image the instance ran when the backup was taken.
    odooVersion string OdooVersion is the Odoo series in the database, such as 18.0.
    pgServerVersion string PgServerVersion is the PostgreSQL server version, such as 16.4.
    databaseBytes integer DatabaseBytes is the size of the SQL dump.
    filestoreBytes integer FilestoreBytes is the size of the filestore.
    filestoreFiles integer FilestoreFiles is the number of files in the filestore.
    addedBytes integer AddedBytes is the new data this backup uploaded after deduplication
    and compression.
    repairedFiles integer RepairedFiles counts attachments that were gone from the filestore
    when the backup ran and were taken from the previous backup instead.
    missingFiles integer MissingFiles counts attachments the database refers to that are in
    neither the filestore nor the previous backup.
    missingFileNames string array MissingFileNames lists the first missing files.
    copies BackupCopy array Copies are the copies of this backup in the instance's other stores.
    warnings string array Warnings name what went wrong around a backup that was still taken,
    such as retention that could not run.

    OdooBackupStore¶

    OdooBackupStore is a place backups are kept: an S3 bucket, an SFTP server, an NFS export or a PersistentVolumeClaim. OdooDeployments in the same namespace name it in spec.backup.stores.

    Field Description Default Validation
    apiVersion string odoo.abugharbia.com/v1
    kind string OdooBackupStore
    metadata ObjectMeta Refer to Kubernetes API documentation for fields of metadata.
    spec OdooBackupStoreSpec
    status OdooBackupStoreStatus

    OdooBackupStoreSpec¶

    OdooBackupStoreSpec is where backups are written to and read from.

    Appears in: - OdooBackupStore

    Field Description Default Validation
    format BackupStoreFormat Format is how backups are kept. restic: one encrypted, deduplicated
    repository per OdooDeployment at <path>/<namespace>/<deployment>/.
    zip: every backup as the zip Odoo's database manager makes, at
    <path>/<namespace>/<deployment>/<db>_<YYYY-MM-DD_HH-MM-SS>.zip (UTC),
    unencrypted; a zip store can only be a copy store (not the first in
    spec.backup.stores) and needs no encryptionKeySecret.    		 restic Enum: [restic zip]
    s3 S3Store S3 stores backups in an S3 bucket.
    sftp SFTPStore SFTP stores backups on an SSH server.
    nfs NFSStore NFS stores backups on an NFS export.
    pvc PVCStore PVC stores backups on a PersistentVolumeClaim.
    encryptionKeySecret SecretKeySelector EncryptionKeySecret is the restic password that encrypts every
    backup in the store. Without it no backup can be read: keep a copy
    outside the cluster. A readOnly store that only holds Odoo zip or
    .dump files, and a store of format zip, do not need one.    		 Optional: {}
    readOnly boolean ReadOnly stores are only read from: OdooRestores and
    spec.bootstrap.fromBackup take backups from them, but no backup or
    copy is ever written there, they are never checked or pruned, and
    their probe only lists the store. Read-only credentials are enough,
    and restic reads the repositories without locking them.
    check StoreCheck Check reads the store's repositories back on a schedule (restic check)
    to find damage before a restore needs them.    		 Optional: {}
    prune StoreSchedule Prune frees the space of the backups retention has removed, on a
    schedule (restic prune).    		 Optional: {}
    timeZone string TimeZone of the check and prune schedules, as an IANA name. UTC MaxLength: 100
    resources ResourceRequirements Resources of the Jobs that probe, check and prune the store. Optional: {}

    lastCheckScheduleTime Time LastCheckScheduleTime and LastPruneScheduleTime are the latest

    lastPruneScheduleTime Time
    nextCheckTime Time
    nextPruneTime Time
    checkRuns integer CheckRuns counts checks, to pick the part of the data the next reads.
    scheduleKey string Schedules the times above were computed for: check, prune and time zone.

    StoredBytes how much they hold together.
    storedBytes integer
    conditions Condition array Conditions: Ready.
