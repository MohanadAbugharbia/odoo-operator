    How backups work¶

    This page explains what a backup is and where it goes. The guides show how to set up a store, take and schedule backups, restore and run restore drills.

    Stores and repositories¶

    Every store holds restic repositories, one per instance under <path>/<namespace>/<deployment>/, encrypted with the key in encryptionKeySecret (keep a copy of it outside the cluster: without it no backup can be read). The kinds of store and their settings are in Set up a backup store.

    What a backup holds¶

    A backup is one restic snapshot holding dump.sql (a plain pg_dump taken with a pg_dump of the server's major), manifest.json (Odoo's own format, plus an operator key) and the filestore/, so it is also what Odoo's database manager restores. Online backups run beside Odoo: the dump, the attachment list and the row counts all come from one database snapshot, so they agree with each other. Files that disappeared from the filestore since (Odoo's attachment cleanup) are taken from the previous backup; attachments in neither are listed in status.missingFileNames and the backup ends CompletedWithWarnings. An online backup waits up to two hours for Odoo's filestore cleanup cron to finish when it is running or due within ten minutes (phase WaitingForFilestoreCleanup). With a ReadWriteOncePod data volume, or consistency: Offline, Odoo is stopped while the backup runs.

    Phases of an OdooBackup¶

    OdooBackup phase Meaning
    Pending Waiting for the instance: one backup, restore or cleanup runs at a time, and backups wait for init, upgrades and rollouts.
    WaitingForFilestoreCleanup Odoo's filestore cleanup runs or is due; tried again every two minutes.
    Running The Job runs.
    Completed / CompletedWithWarnings status.snapshotID holds it.
    PartiallyCompleted The backup is in the first store, but a copy to another store failed; status.copies says why.
    Failed status.message names the step that failed and the Job to read.

    Deleting an OdooBackup does not delete the snapshot, and deleting an instance never deletes its backups.

    The backup image¶

    The Jobs run ghcr.io/mohanadabugharbia/odoo-operator-backup at the operator's own tag (derived from the operator's image; --backup-image overrides it). It carries the PostgreSQL 14–18 clients, restic, rclone and the odoo-backup agent, and runs as the instance's pod security context with no service account token.
